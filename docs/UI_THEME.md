# UI 主题维护与协作

## 修改位置

Nord 精调主题独立放在 `web/themes/nord-refined.css`，通过 `web/index.html` 的样式链接和 `data-ui-theme="nord-refined"` 启用。语义颜色、侧栏宽度在文件开头；卡片、控件、总览和窄屏布局在对应选择器中。主题限定选择器范围，不复制整份公共或模块 CSS。

`web/styles.css` 继续维护公共组件基础样式，模块样式通过 `context.ui.useStyle` 注册与清理。新增模块继续使用现有变量、组件和模块清单导航，不需要向主框架添加业务 ID。

## 本次交互范围

- `web/app.js`：保留主线分类与分页布局，补充跳至主内容、切页焦点，以及非分页分类的页面分区入口。快捷按钮保持当前 hash、表单草稿与模块生命周期。
- `web/index.html`：主题入口、键盘跳转链接和 SVG 菜单按钮。
- `modules/dashboard/web/index.js`：全部来源未连接时统计显示 `—`、提供连接引导；保留独立错误、近期作业、日程和通知。第四项统计使用已有 `ready_sources` 字段。
- `checks/check_ui_theme.mjs`：主题和交互回归，与现有 `checks/check_web.mjs` 分开。

本次不修改启动器、依赖、接口字段或来源同步行为。后续涉及这些 UI 文件的结构改动，应在 PR 中说明与主题选择器及调用方的关系。

## 调整与同步

团队更新后保留公共和模块的新功能，再检查主题覆写是否仍匹配新结构。接口、模块分类和 CSS 类名发生变化时，即使 Git 没有同文件冲突，也需要验证页面。

移除 HTML 的 `data-ui-theme` 属性可对照基础外观，不需要改动接口或组件实现。启用主题后的卡片、按钮、菜单、错误反馈都应保留文字含义和可见键盘焦点。850px 以下沿用遮罩导航；375px 和横屏不得让整个页面横向滚动。

## 验证

先使用团队启动入口运行本机网页，在项目根目录执行：

```powershell
node.exe checks/check_web.mjs http://127.0.0.1:16666
node.exe checks/check_ui_theme.mjs http://127.0.0.1:16666
```

主题检查覆盖真实未连接总览、合成有数据与无数据状态、日程、独立错误保留、1440/768/375px 与横屏、主题开关对照、设置草稿、快捷跳转、模块分页与样式释放。测试使用单独的隐藏浏览器和合成响应，不读取真实凭据、不发起登录或付费 AI 请求。截图保存到 `.codex/tmp/`。

公共框架与业务回归仍按 `check.ps1` 或 `check.sh` 验证。UI PR 合入前由团队检查最新主线与实际变更，其他成员随后更新本地分支。

首页打开时先显示学习助手，总览随后显示，视觉顺序与页面挂载顺序保持一致。首页总览使用 `overview-compact` 变体，将四项统计保持在紧凑的一行，待办与日程按需展开。主题集中维护此变体的间距与窄屏布局。页面分区入口位于页面标题旁；学习助手根据卡片实际位置和视口高度调整对话区，保持输入区在底部。结构变动后同时检查常规主题与紧凑变体，以及学习档案、设置深层链接和样式释放。

首页开始或恢复有消息的对话后通过通用 `context.focus(true)` 收起其他卡片，阅读宽度至多 1120px，输入跟随视口。历史对话使用遮盖式面板，手机下保持可关闭与可滚动。邮件、课程和通知的局部样式分别位于所属模块，沿用 `--paper/--surface/--text/--muted/--link/--border`；常驻通知入口使用自己的样式并避开发送按钮。运行 `node checks/check_campus_workspace.mjs` 检查分栏、段落、课程主页面、参加确认和后台提醒，截图仅用于本地开发验证。
