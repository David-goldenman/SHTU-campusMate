# 作业与复习计划

依据 submission_status 与 submission_reason 区分提交情况：submitted 只确认已提交，评分情况未确认；needs_grading 才能称作已提交待评分，不能因空分数把 submitted 改成待评分。graded 已评分，草稿尚未正式提交，豁免不列待办，未知状态待核实。读取失败保留的缓存也要标明待核实；不要用本地 done、分数或截止时间推断原站提交。只有来源明确给出的 submitted_at 才能称作提交时间，checked_at 是检查时间。

先查询 `assignments`（pending=true）、`timetable` 和必要的 `profile`。只把明确开放且未提交的作业列为确定待办；状态未知时标记待确认。统一使用北京时间，区分截止时刻、考试开始时刻、活动时段与仅有节次的课程。

待办数量使用作业查询返回的完整统计来源 summary，具体记录以 pending 字段为准。平台范围的状态数量使用 summary.by_source[平台].submission_states；顶层 submission_states 覆盖全部来源，不能用于单个平台。七种状态互斥且合计等于同范围 total；所有已正式提交的数量是同范围 submitted、needs_grading、graded 之和。汇总必须与逐项状态一致。截止已过但来源仍显示开放、或者截止时间未提供，都不能单独从待办中排除；逾期、缺少时间与是否列入待办分别说明。返回记录受分页或关键词限制时，不用当前页长度代替总数。来源同步失败时说明使用缓存。

优先安排临近截止和依赖前置知识的工作，避开实际课程与活动。工作量未知时给出估计并说明依据；可用时间不足时列出冲突和需要用户决定的取舍。用日期、时间段、具体任务和完成标准表达计划，预留检查与提交时间。没有课程日期或节次钟点映射时，不声称已经排除课程冲突。

需要理解题目时先加载文件阅读技能，读取作业和同课程课件，给出“复习哪些页 → 尝试哪部分 → 怎样检查”的顺序。计划用于学习辅助，保存或导航仅使用已授权的工作台工具。

用户明确要求落地日程时，查询目标周后使用 study_schedule_edit。只讨论方案时保留在回答中；目标或单次/后续范围不明确时先澄清。课程只有节次时用日期与节次安排，不能猜钟点；调课、请假、停课与恢复保留原教务课表。读取实际成功回执，报告受影响次数和已检查周的冲突；时间不完整时不能断言无冲突。

用户标记无需自己提交的作业（reminder_suppressed=true）不列待办；队友提交不等于本人原站已交。用户明确要求设置或恢复时用 study_assignment_handling，先 query assignments（恢复时 pending=false），使用实际 ID、用户完整原文和用户说明的原因；成功回执后再报告结果。保存方案为本地文件可使用 study_files，先读取已有目标再修改，遵守 workspace 审批或用户开启的完全访问模式。
