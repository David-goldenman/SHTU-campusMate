# 首页学习助手

查询作业时使用来源的具体提交状态、依据及检查时间：`submitted` 只确认已提交、评分情况未确认，只有 `needs_grading` 才能称待评分；空分数不能证明尚未评分。草稿仍需正式提交，豁免不列待办，未知或读取失败要说明待核实。`summary.submission_states` 与 `needs_review` 是全部缓存的状态统计，单个平台使用 `summary.by_source[平台]` 中的同名字段，不能混用统计范围或把当前页当总数。七种状态互斥，所有已正式提交是同范围 `submitted/needs_grading/graded` 之和；本地完成进度、原站提交、开放状态和截止时间分别说明。

首页默认打开完整聊天区域，“校园概览”可切回首页摘要。空对话时，问候、输入框与常用问题集中在页面中间；开始聊天后，消息在居中阅读区滚动，输入框固定在底部并随内容自动增高。历史面板可搜索标题，区分进行中与已归档；宽屏以侧栏展开，窄屏使用抽屉，支持新建、切换、归档、恢复与删除，学习档案独立保留。归档可阅读，恢复后继续发送。

Enter 发送，Shift + Enter 换行；兼容 Ctrl／Command + Enter，中文输入法确认候选词不会触发发送。主动点击“新对话”或“历史对话”展开聊天区域，空会话也可重新打开。在工作台内切换页面时，当前回答继续生成；返回首页会恢复原问题、工具进度与已生成内容，离开期间完成的回答只展示一次。未发送的输入也会恢复。只有主动停止、模块卸载或整个网页关闭／刷新才取消当前请求；旧模型仍在清理时，新建与选择会话立即可用。

## 多会话接口

`GET /conversations` 返回 `{items:[{id,title,created_at,updated_at,archived}],active_id}`；`POST /conversations` 新建并选中，201；`POST /conversations/{id}/select` 返回 `{conversation,messages}`；`PUT /conversations/{id}` 接收 `{archived?,title?}`；`DELETE /conversations/{id}` 删除本地对话及消息。标识为 32 位十六进制，账号外的记录返回 404。`GET /chat` 返回 `{messages,conversation_id,owner}`，`owner` 是共享账号组合版本，用于隔离页面内的草稿和生成状态；`POST /chat` 和 `/chat/stream` 可带 `conversation_id`，省略时使用当前对话或创建首段对话。向已归档对话发送返回 409。

索引、完整消息和当前选择存入模块 Store，按共享账号组合版本隔离，重启恢复。首次访问迁移已有单段历史，之后通过索引管理，删除后不会重新导入。标题取首次问题；发送失败或中断不保存半段消息，重试仍在同一对话。生成中可以新建、查看其他对话，历史列表标注“正在生成”，新对话提供直接返回入口；同一网页一次生成一轮，其他对话可先编辑草稿，上一轮完成后再发送。`DELETE /chat` 作为兼容入口删除当前对话。

`study_attend` 通过 `/tools/attend {proposal_id,quote}` 接受已读通知中的活动建议，须有用户本次明确表示参加／加入时间表的原文。后端同时检查 quote 中的明确意愿和整条当前消息的否定、条件与疑问上下文。引文中的活动标题必须唯一对应目标建议；“这场活动”等指代仅在本次只读取一项建议时接受，不能用参加 A 的意愿确认 B。否定、条件、疑问、带引号的转述、目标含糊或未读建议返回 422。含糊或复杂表达可先明确确认，或直接点击通知中的参加按钮。成功后通过后台助手的幂等导入写入时间表；不修改原站报名状态。

独立的首页聊天与原生 Harness 插件，模块 ID 为 `academic-assistant`。在设置中启停该模块即可控制首页入口和工具；模型与 Key 使用共享 AI 服务。工具通过已有模块公开 API 按需读取课程、作业、时间表、通知、邮件、已有课程记录与培养方案，检索课程资料和录播原文，读取 PDF／PPTX 页级文字，并查询教务课程目录与大纲。回答返回可核对的来源与原文片段，可按用户要求打开工作台页面。

## 接口与资料

前缀为 `/api/v1/modules/academic-assistant`。`GET/POST/DELETE /chat` 读取、发送和清除聊天；`GET/PUT/DELETE /profile` 管理本机学习档案；`GET /activity` 查看当前任务的工具进度，`GET /presets` 返回 `{items:[{label,prompt}]}` 常用问题。用户档案包含专业、入学年份、未来方向、每周可用学习时间与备注，培养方案作为带来源的学业记录单独保存。聊天按共享账号版本隔离，档案和学业记录按已验证的 IDS 账号隔离。

原生工具由 `harness/` 注册，使用一次任务有效的本机令牌访问 `/tools/query`、`/tools/search`、`/tools/document`、`/tools/course-search`、`/tools/navigate`、`/tools/remember`、`/tools/attend` 和 `/tools/finish`。令牌通过服务端 `plugin_env` 注入运行时，不进入模型提示；接口仅在该任务存续、账号版本相同时接受调用。工具返回的引用保存在任务内，模型先通过 `study_finish` 提交引用和 `insufficient_context`，后端核对实际来源及字词顺序，允许排版空白差异，保留引用片段的连续原文。校验失败由模型在本次任务中修正，通过后再以普通 assistant 消息流式生成 Markdown 正文。完整任务成功且账号版本仍一致时才保存聊天；最终事件附上已核对的引用卡片。原生 `study_finish` 不接收正文。HTTP 接口保留可选兼容字段 `text`，只在最终 assistant 正文为空时使用，不能覆盖已经流式显示的完整回答。

学习规划根据明确的待办、截止时间、已公开的作业状态和用户可用时间提出建议，估计工时与学校要求分别说明；课件引用显示真实页码。选课建议结合历史修读记录、培养方案、课程目录／大纲和用户方向，区分学校要求与建议，学期实际开课需要另行核对。用户明确要求记录本次消息中的个人信息时，工具核对原文后保存；用户也可在档案表单中编辑或清除。

PDF、PPTX 和 UTF-8 文本按需通过 Blackboard／Gradescope 文件 API 下载及解析。单文件至多 30 MB，PDF／PPTX 至多 1000 页，PPTX 文字 XML 合计至多 40 MB；每页提取至多 20000 字符，每次返回至多 12 页、每页片段至多 6000 字符。PPTX 页码遵循演示文稿实际顺序。扫描页／图片和旧版 `.ppt` 暂需在原文件查看。提取文字缓存在本模块 `data_dir/documents/<账号组合版本>/`，由来源更新时间区分版本，引用保留原文件入口。

首页显示资料会发送至所选模型服务的说明。助手按问题读取课程、作业与 DDL、时间表、课件文字、录播、讨论、相关通知／邮件、已有课程、培养方案及学习档案；学校凭据和会话由原服务维护，短期工具令牌留在本机。当前工具版本最近 8 条消息的文本和个人偏好作为连续对话上下文，每条历史文本至多 2500 字符；本机按会话完整保存已完成的消息。历史按所有共享服务的账号版本隔离，个人档案与学校记录按 IDS 隔离。新建、归档、删除对话及清除档案分别通过首页操作；完整模块文件可通过设置清除模块数据。

来源缓存、教师课件及工具输出作为学习资料处理。允许明确授权的本地日程与学习事务编辑，文件解析、本地进度与规划不改变原站作业或选课状态。

## 日程与学习事务

`study_query(area="timetable")` 保留 `week_one`、`week_one_source`、`teaching_week` 和来源提示。日期来源为 `manual`、`school` 或 `null`。有课表但没有确定的学期起点时，课程不展开为具体日期，工具返回资料不足提示及不完整的冲突检查；已有个人安排与截止事项继续返回，不能把缺失课程理解为本周无课或没有冲突。

主页支持通用知识讲解、题目分析、代码与写作辅助，无需校园资料时使用 `study_finish(basis="general",citations=[])`，不强行查询私人数据。具体校园事实仍需读取实际来源并核对引用。`study_capabilities` 返回当前能力与时间表模块可用状态。

`study_schedule_edit` 通过时间表公开 `/commands` 接口编辑 Quiz、考试、习题课、学习等个人安排，或为具体课程记录请假、停课、单次/后续调课与恢复。写入前查询对应周时间表，记录 ID 和版本来自本轮实际读取结果，后续范围须由用户明确指定。完整当前消息作为 `quote`，否定、条件、讨论及引用资料中的指令不授权修改。成功回执才表示保存；回执显示修改前后、范围与有限的冲突检查。学校端审批、正式调课和报名仍由原系统办理。

`study_work_edit` 管理本地作业状态、一次性提醒和学习计划，`study_query(area="workspace")` 查询记录。`set_assignment` 在查询作业后以原作业 ID 更新 `todo/in_progress/done/cancelled` 及备注；`local_status` 与来源 `submitted` 分开呈现，不覆盖原站状态。`create` 新增 `reminder/plan`；`update/delete` 操作本轮读取的学习事务。提醒需要带时区的 `due_at`，计划正文放 `notes`。只要求生成方案时保留在聊天里，明确要求保存才创建记录。

首页“对话操作 → 学习事务”可以查看、手动编辑和删除记录，也可新增提醒/计划。`GET /work` 返回 `{account_revision,items,changes,reminder_delivery}`；`POST /work/commands` 请求 `{action,request_id,account_revision,record_id?,expected_revision?,item?}`，动作与工具一致。`create` 字段为 `{kind,title,status?,notes?,due_at?}`；提醒时间必填。`set_assignment` 使用来源作业 ID、最新 `local_revision`（首次为 `""`）和 `{status,notes?}`；其他修改使用学习事务的 `id/revision`。版本过时或账号变化返回 409。记录与最近 200 条幂等回执在同一次本地存储写入中保存，按账号组合版本隔离。

提醒由模块管理的后台线程约每 30 秒检查，通过通知模块公开 `/imports` 发往本地通知中心，不调用模型、不发邮件或外部推送。服务关闭期间不执行，下次启动补发到期提醒；通知模块不可用时保留待发记录并重试。删除、取消或完成后的提醒不再发送；已发送的历史通知保留。修改到新的提醒时间会重新安排一次通知。停用模块会停止并等待该线程，重新启用保留记录。

聊天流新增 `change` 事件 `{change:实际回执}`，完整回答含 `changes`。停止或连接中断时页面保留已收到的回执；如果写入成功后模型失败，后端仍保存包含实际修改的简短答复，避免提示用户盲目重复执行。未发生写入的失败继续保持原有历史行为。`GET /work` 及时间表 `/changes` 可独立核查持久操作记录。引用 ID 与原文校验照常执行。

## 请求与结果

发送 `POST /chat`，例如 `{"message":"核对本周未完成作业，结合截止时间与课表安排学习。"}`。`message` 为 1–8000 字符。返回助手消息 `{"role":"assistant","text":"…","citations":[{"source_id":"…","title":"…","quote":"…","url":"…","page":3,"download_url":"…"}],"navigation":null,"tools":[{"name":"study_query","is_error":false}],"model":"deepseek-flash","created_at":"…"}`；引用仅保留实际可用字段。空问题或参数越界为 422，账号切换或 AI 未配置为 409；运行时失败或尚未提交已校验回答为 502。来源未连接等工具错误交给模型解释，缺少资料时可返回明确说明。

`PUT /profile` 接收完整个人档案；专业至多 120 字、方向 1200 字、备注 4000 字，`cohort_year` 为 2000–2100 或 null，`weekly_hours` 为 0–168 或 null。`GET /profile` 返回 `{profile,academic:{plan_title?,updated_at?}}`。培养方案在实际查询时更新。

首页使用 `POST /chat/stream`，请求体同 `/chat`，响应为 `application/x-ndjson`，每行一个 JSON 事件，按顺序处理：

| type | 字段与行为 |
| --- | --- |
| `activity` | `steps:[{name,label,status}]`，准备或工具执行状态 |
| `reset` | 开始新的模型输出尝试，清空当前临时正文 |
| `delta` | `text`，引用核对通过后的正文增量；不发送推理或工具参数 |
| `complete` | `message`，与普通 `/chat` 的助手消息一致，替换临时正文并显示引用 |
| `error` | `status`、`detail`，任务失败；保留输入，聊天历史保持原状 |

只有 `complete` 表示回答完成。连接提前结束时前端提示重试；停止生成会取消请求、通知运行时结束任务，并等待后台释放工作区和一次性令牌。配置准备和插件安装阶段也会检查取消并回收本次进程树，SDK 初始化受 30 秒时限约束。任务总时限为 600 秒，流式连接连续 240 秒没有事件时提示超时。中断的半段正文不保存到历史。页面切换使用同一次流式请求，不重新发问；完整网页刷新、关闭后不恢复未完成任务。

工具查询支持关键词、课程与分页，默认返回 30 项、至多 60 项；材料／讨论检索默认 12 项、至多 30 项。录播原文查询返回已有转写片段和时间点，不下载录播视频。工具步骤达到 24 次后保留最终回答提交入口，其他操作需缩小范围继续对话。

作业查询额外返回可引用的 `summary` 来源，内容来自作业管理公开 API 的完整统计，并附 Blackboard/Gradescope 各自的缓存状态和更新时间。它覆盖当前账号全部缓存作业，不受本次关键词、课程或分页限制；工具原有 `total` 仍表示筛选后的记录数。全局及分平台的未提交/待办数引用该统计；指定课程范围时读完相应分页并使用记录的 `pending` 字段，不因截止时间已过或缺失自行排除。来源同步失败时明确说明使用缓存。

## 开发与验证

前端复用 Nord 变量、共享组件与注入上下文。`web/background.js` 用常驻模块上下文持有流式请求，`session.js` 保留当前轮次和按账号隔离的内存草稿；页面离开时移除订阅、渲染帧与样式，返回重新订阅。模块卸载、账号版本变化时中止并清空临时状态，不写浏览器本地存储。后端任务通过官方 `context.ai.run(..., plugins=["academic-assistant"], on_event=..., cancel_event=...)` 执行，使用期间遵循模块请求计数；任务结束释放一次性令牌，模块停止释放内存任务。共享 Markdown 渲染器使用本机提供的 markdown-it 15.0.3，关闭 HTML，沿用解析器的链接校验，图片仅显示描述。合成检查覆盖中文跨字节分片、Markdown 安全、引用核对、取消任务及失败后保留历史；`check_session.py` 将页面离开／返回、后台完成、单次请求、停止、账号隔离与模块卸载回归纳入统一检查入口。

宿主在 `.private/runtime/tmp/harness-*/workspace/` 创建任务工作区。原生插件用 `process.cwd()` 读写其中的 `study-<序号>-<工具>.json`，保存工具参数、实际读取结果与已核对的回答，供当前任务分析使用；令牌不写入文件。任务结束工作区自动清理，长期对话、档案与课件文字缓存由本模块的 Store 和 data_dir 保留。工作区及其他私有运行数据均由 Git 忽略。

使用合成 API 与文档验证工具、引用、账号隔离和个人信息更新；使用官方运行时验证实际工具调用。真实服务验收由用户在设置连接后进行。

启动 demo 后运行 `node modules/academic-assistant/checks/check_web.mjs http://127.0.0.1:16666`，在独立 Edge 窗口验证渐进 Markdown 渲染、引用分组、复制、阅读位置、桌面／手机尺寸的输入框、停止、失败重试、连接中断及 AI 设置跳转。测试窗口阻止真实 API 请求，使用合成流与资料；截图及浏览器资料保存在项目开发目录。

## 校园规则与技能

真实模型的主页交互验收使用独立数据目录，入口与复测记录见 [主页对话验收](checks/LIVE_ACCEPTANCE.md)。该流程需主动启动，不属于自动检查；自动回归仍全部使用合成模型响应。

`harness/AGENTS.md` 定义校园学习场景、简明沟通、证据与个人信息边界；`server/instruction.md` 约定工具和回答校验；`harness/prompts.json` 提供首页常用问题。`harness/skills/` 内的文件阅读、作业规划与培养方案技能通过官方注册表及 `skill` 工具按需加载。新增技能遵循相同结构，使用工作台现有工具，随插件启停。规则不包含开发环境要求。

校园概览中的课程、作业与资料摘要按需查看；聊天采用约 780px 的居中阅读宽度。工具进度显示在对应回复中，详情按需展开；错误保留输入并提供重新发送。阅读旧消息时暂停跟随，点击“回到最新回复”继续跟随生成。长回答支持标题、列表、表格、引用和代码块；表格、代码在内容区内滚动，回答及代码可复制。同一份文件的引文合并展示并标注编号、页码与原文件入口。学习档案按需打开，模型链接直接进入统一 AI 设置。已有本机聊天记录保留，连续对话使用当前工具版本写入的消息。底层运行与权限边界见 [AI 文档](../../docs/AI.md)。
