# 作业管理

依赖课程中心公开 API。`GET /snapshot` 汇总 Gradescope 与 Blackboard 作业，返回按发布时间倒序的列表、五类计数 `counts` 与按截止时间排序的 `pending`。`pending` 仅包含本学期仍可提交的项目（含迟交），供主页统计使用。

## 调整顺序
待完成、迟交、已批改、已完成和已结束五个分区内的卡片可拖动排序，也可聚焦卡片后按 ↑/↓ 或使用卡片右侧箭头移动。顺序通过 `PUT /order` 按账号版本保存在本机 Store 中，刷新后保持；新增作业追加到末尾，来源列表变化时服务端拒绝过期顺序并提示重新排序。

- `pending`：未确认已提交、来源开放且尚未截止；缺少截止时间时只要来源开放也归入该类。
- `late`：未确认已提交、来源开放但已过截止时间，`overdue=true`。
- `graded`：已提交且已公布分数（`0` 分同样有效），页面单独突出显示得分。
- `completed`：已提交但尚无分数。
- `ended`：来源已关闭、尚未开放或开放状态未知；只有明确提交才归入完成类，开放但提交状态尚未解析的项目仍提醒待办。

页面按待完成、迟交、已批改、已完成、已结束的顺序分区，可按学期和关键词筛选。`POST /sync` 通过课程中心更新已配置来源。`GET /detail?assignment_id=规范ID` 实时读取 Gradescope 详情或返回 Blackboard 已缓存题目资料；资料下载使用所属来源模块的公开地址。模块不读取其他 Store。项目 `check.sh` 验证五类状态、零分成绩、未知提交／开放状态与历史课程。
