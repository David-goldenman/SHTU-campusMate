# 校园地图

提供本地校园建筑图、室外步行路线、当天安排的时间／事项／教室与建筑定位，以及有校方出处的电梯位置说明。独立分类为 `campus-map`，通过模块清单注册，框架无需增加业务分支。

## 数据与范围

博士公寓 11、12、13 号楼名称与北到南顺序依据 2026-10-18 使用者更正。三栋楼的轮廓已替换为[浦东新区 2024-10-24 公布的上科大二期工程设计方案](https://www.pudong.gov.cn/zwgk/14496.gkml_zhzw_ghjh/2024/298/333431.html)中灰色楼体的矢量边界，保留各自折角与楼间空隙，不再沿用或拆分旧球场范围。公示图的工程编号 3#、2#、1# 分别对应当前北到南的 11、12、13；详情区明确注明设计方案依据及“未核验竣工实况”，不把图纸轮廓解释为现场测绘或入口坐标。

`data/doctoral-footprints-source.json` 保存公示图链接、PDF 原始顶点、12 个配准点及仿射矩阵。配准点来自 OSM 中 8、9、10 号公寓主楼四角（ways 587641176、587641175、587641174）；从 PDF 页坐标拟合到 WGS84，再沿用下述 GCJ-02 → BD-09 转换。控制点残差 RMS 约 0.92 米，仅表示两份资料的局部吻合度，不是绝对定位精度。配准所用 OSM 数据及其衍生成果遵循 ODbL 1.0，© OpenStreetMap contributors；转换库仅用于离线导入，运行时无新增依赖。

旧健身场多边形与 13 号楼公示轮廓重叠，本次一并移除旧地点，条目共 65 个。[学校 2022-08-31 搬迁设计公告](https://www.shanghaitech.edu.cn/2022/0831/c1528a804892/page.htm)已将该东北三角地块的篮球场、排球场及器材区纳入搬迁范围；新器材区轮廓尚未核实，不推断其具体位置。

`data/places.json` 初始收录的 65 个建筑／校门轮廓及校园边界取自[学校官方地图](https://map.shanghaitech.edu.cn/)在 2026-10-17 返回的公开数据，保留其 BD-09 坐标；随后按上述依据更新博士公寓及旧场地。保存建筑名称、类别、几何、别名和来源说明。其中 5 处校门提供短名称与地址，可直接点击定位。地图在本地绘制，打开页面不加载第三方地图脚本，也不向校外发送个人日程。

建筑图支持缩放、平移、搜索、键盘操作、展开地图和当天地点标记。楼名以 14px 屏幕字号显示，不随全图缩放变小；标签按所选地点、校门、当天安排、常用建筑的顺序避让，放大后显示更多楼名，也避让地图操作按钮。它是建筑级定位，不把建筑中心解释成教室门口或电梯精确坐标。

在地图内拖动可平移，滚轮以指针所在位置为中心缩放；右下角按钮和键盘 `+` / `-` 以当前视野中心缩放，`0` 返回全图，方向键平移。点击或用 Enter / 空格选择楼体、楼名后可继续使用方向键。4px 内的点击抖动不会移动地图；拖动结束不触发地点选择，指针取消、失去捕获、窗口失焦及模块卸载均结束拖动。地图画布内禁用文字选择，搜索与详情仍可正常选字。`checks/check_interactions.mjs` 覆盖点击与拖动分界、取消清理、额外指针、滚轮单位及缩放锚点，随原有模块检查执行。

`data/osm-basemap.json` 单独保存道路、步行道、水系和绿地，来自 [OpenStreetMap 校园范围公开数据](https://api.openstreetmap.org/api/0.6/map?bbox=121.5835,31.1745,121.5968,31.1835)，查阅于 2026-10-17。本次使用参考 HTML 的地图分层思路，并重新下载覆盖整个校园的底图，不包含参考文件中的活动目标或测距记录。271 条道路线段与 68 个景观要素仅用于方位显示；不由此推断道路开放、无障碍通行或地下路线。

OSM 衍生数据按 [ODbL 1.0](https://www.openstreetmap.org/copyright) 提供，版权为 © OpenStreetMap contributors，地图上保留可见署名。原始 WGS84 坐标在离线导入时通过 [coordtransform 2.1.2](https://github.com/wandergis/coordtransform)（MIT）依次转为 GCJ-02、BD-09，与校方建筑图对齐，文件保留转换说明和 OSM 要素 ID。转换只用于底图显示，不作为测绘精度保证；运行时不需要坐标转换库或新依赖。OSM 文件与校方建筑数据分开保存，各自保留来源。

电梯资料目前覆盖图书馆与创意与艺术学院，共三条楼内位置说明。地图按所属建筑标记，详情保留楼层、位置原文依据和出处链接；查阅日期不表示现场核验，未收录不表示没有电梯。没有完整室内路网，不推断无障碍通行条件、开放状态、停靠楼层或地下车库体育课路线。图书馆的两条位置说明不推断为两台独立电梯。

- 图书馆一楼东门电梯口：[其他设施](https://library.shanghaitech.edu.cn/3992/list.htm)。
- 图书馆一楼大厅中部电梯口：[小组讨论室](https://library.shanghaitech.edu.cn/2018/0814/c3989a31486/page.htm)。
- 创艺学院东南角电梯、地下车库 C/B 区交界附近的进入说明：[联系我们](https://sca.shanghaitech.edu.cn/2018/0803/c4123a31066/page.htm)。

地下体育场地路线尚未核实，按本次需求暂不实现。已有课表中的体育馆 B107 等地点仍可定位到体育馆，教室名称保留来源原文。

## 接口与日程

前缀 `/api/v1/modules/campus-map`：

- `GET /places` 返回上述公开建筑、电梯说明及来源元数据，以及 `basemap` 内的 OSM 道路与景观数据。
- `GET /walking-network` 返回 ODbL 许可的公开 OSM 道路、节点、步行权限标签、校园边界和来源。与日程解耦，时间表不可用时仍可选择公开地点规划。
- `GET /conditions` 返回当前共享账号组合版本的通行记录、记录集 `version`、`account_revision` 与最近 200 次修改摘要。未保存时提供一条明确标为待核实的西门线索。
- `POST /conditions`、`PUT /conditions/{id}` 接收 `{version, account_revision, item}`。`item` 包含标题、`state`（pending/confirmed/resolved/withdrawn）、`effect`（blocked/caution）、`scope`（place/edges/area）及对应的地点 ID、OSM 稳定道路引用或矩形边界；另含 `starts_on/expected_end/review_on`、`source_kind/source_title/source_date/source_url/note`。数据错误返回 422，账号或版本冲突返回 409。日期采用北京时间自然日。
- `POST /conditions/undo` 接收 `{version, account_revision}`，撤销最后一次本地修改并追加审计记录；新增记录撤销为已撤回，不直接删除历史。
- `GET /day?date=YYYY-MM-DD` 默认北京时间今天，仅经公开 `context.api('timetable','/schedule?week_start=...')` 读取所选日期的日历。返回日期、精简日程、来源状态、更新时间和问题提示；不触发学校同步、AI 或任何写入。读取前后检查账号版本，切换账号返回 409。

课程取消、请假和调课原位置不作为去向；保留调课后的实际安排。事项的截止时间仍标为截止，不转成上课开始时间；没有钟点时保留节次，没有地点或匹配有歧义时明确提示。地名匹配仅使用明确建筑名／别名，含多个建筑的描述不会自动选一个位置。时间表模块关闭或不可用时，地图与电梯资料仍可用，日程区明确提示。

页面链接可带 `#campus-map?date=YYYY-MM-DD&event=事项ID` 或 `&location=教室原文`，只在本机定位。资料不缓存用户日程，离开页面中止请求、事件、观察器和样式。通行维护记录使用本模块 `context.store`，纳入框架备份；旧 IDS 公共维护记录兼容保留，新记录在 IDS 分区内再按共享账号组合版本隔离，避免切换邮箱后泄露邮件依据。账号切换拒绝旧表单写入。验证由模块 `checks/` 执行。

## 试用版本

### 室外步行

选择起点和终点即可计算，也可从地图详情设为起点，或在当天安排点击“步行到这里”。课程终点保留日期、时间、教室原文；换日期时清除课程终点，手动选定的公开地点不会写入账号数据。初始不假设当前位置，不请求 GPS。地图高亮道路并提供约计米数、步行时间、方向说明、交换起终点、查看全程与清除。

`data/walking-network.json` 从同批 OSM 原始资料独立导入，保留真实节点 ID，不把底图交叉线当作路口。校园边界来自 OSM relation 5390610 的闭合外轮廓。`web/routing.js` 仅连接共享节点，排除校外道路、地下／室内道路、非步行主干道和明确禁止步行的路段；高架层仅保留标有桥梁的道路。采用距离最短路径，按 80 米/分钟估算时间，不计入进楼与等候时间。路网缺失、断开或地点附近 60 米内没有可用道路时明确提示，不补画直线。

起终点选在建筑／校门轮廓附近的已收录道路上，路线不进入建筑，也不把邻近道路点宣称为已核实入口。OSM 与校方建筑资料存在测绘、坐标转换和更新时差；数据收录时间不代表实地核验，临时封路、门禁、无障碍条件以现场为准。走路步骤和距离仅作试用参考。路线计算完全在浏览器进行，不向外部发送地点选择或课程。室外台阶会在结果中提示。

体育馆采用 2026-10-17 使用者反馈的入口侧向：地图左侧（西侧）有两个入口，原先右侧到达点附近的入口不常开。`walking_approach` 将到达／出发道路限制在西侧，缺少可用道路时不回退到另一侧。该反馈与校方建筑来源分开标注，精度仅为建筑一侧，不虚构两个门的精确坐标；地图与课程路线显示“西侧入口附近”。

验证增加最短路径、同一路段起终点、方向限制、相交但未连通道路、室内／地下／权限过滤、校园边界，以及北门至六处课程建筑的真实路网覆盖。`check_routing.mjs` 由原有模块检查执行。

### 施工与通行维护

入口在路线摘要“维护 / 复核”，也可展开地图下方的“施工与通行维护”。支持地点、地图选路段、两个对角点圈选区域；保存前显示影响范围，保存后即时重算路线。已确认的步行封闭从路网中排除，封闭地点不作为起终点；人工待核实记录默认提示，可主动选择避开。所选日期到达复核日或超过预计完工日时显示需复核，已确认封闭保持避让，恢复需新依据。任意维护来源链接只供用户查阅，不由后端抓取。

### 自动发现与人工确认

“施工与通行维护”内的自动发现支持检查一次、每 30 分钟检查、暂停及公告／邮件来源选择。代码默认关闭定时检查，由使用者启用；应用运行期间由本模块 `start/stop` 管理唯一检查线程，切页后可继续，退出应用或停用模块时取消并等待任务结束。无需 AI、外部爬虫服务或新依赖。

公开来源固定为[校方公告首页](https://www.shanghaitech.edu.cn/1004/list.htm)近 90 天内的最多 20 篇文章，实际首页目前最多 14 条；只读取该站同域公告正文，不跟随重定向，不下载附件。邮箱通过文档化 `mail /snapshot`、`POST /sync`、`GET /message` 读取最近最多 100 封缓存，并请求同步；筛查其中近 90 天的文字，每轮最多补读 20 封正文，后续轮次继续。正文读取不更改邮件已读状态。邮箱停用、登录或同步失败时保留已有发现并明确显示覆盖不足，不偷偷启用依赖。界面分别显示分批等待、读取失败和需要登录的数量；需要登录时不继续逐封请求缺失正文，并提供账号设置入口。来源读取前后检查账号版本；正文不发送给模型。

本机规则筛选施工、封闭、绕行和恢复文字，保存连续原文片段、来源链接、发布日期、原文日期文字与建筑候选。它不做完整语义理解；图片、附件、校内未公开网页、历史分页以及超过读取范围的内容可能遗漏。无日期／多地点／预计或否定语气／机动车限制均需核对。发布日期不自动填为生效日，也不凭文字推测精确道路。网站正文结构变化或网络失败显示失败，不解释成“没有封路”。

发现始终进入独立的**待核实列表，不参与任何路线避让**。用户查看原文，选择新建或关联已有记录，核对日期和地图范围，勾选核实后保存才生效。恢复线索必须选定已有的已确认限制，补充新依据并人工确认；“预计恢复”不会自动识别为已经恢复。重读相同来源和片段去重，保留忽略／已处理决定；同一来源的片段更新会让旧待核实版本失效并新建线索，不修改已确认记录。撤销已应用记录不会重新导入同一来源。

接口前缀同上：`GET /discovery` 返回设置、运行状态、来源覆盖、当前账号的发现、`version/account_revision`；`PUT /discovery/settings` 接收 `{version,account_revision,enabled,official,mail}`；`POST /discovery/check`、`POST /discovery/{id}/dismiss` 接收 `{version,account_revision}`。确认时仍调用 `/conditions` 的新增／更新接口，额外传入 `discovery_id/discovery_account/evidence_confirmed`；来源、账号、未处理状态及恢复关联均由后端检查。已确认的发现保存来源 ID 引用，拒绝重复应用；人工修改保留来源关联。所有写接口沿用框架 CSRF。待核实发现上限 300 条，保留最近 500 条已处理线索和 2000 份来源处理标记。

`check_discovery.py` 使用合成公告与邮件，检查待核实隔离、必须确认、恢复关联、重复／原文更新／忽略、取消、账号切换、依赖缺失及线程清理；真实账号不作为回归夹具。

记录保存失败保留表单；多标签页冲突要求刷新再核对。维护接口不可用、已确认限制失去底图定位时暂停路线，地图仍可用。撤回／恢复保留历史，支持撤销上次修改；进行中的记录上限 300 条。基础地图资源升级与本地维护记录独立。详细设计、维护节奏、数据更新流程与边界见 [维护方案](MAINTENANCE.md)。

地图作为独立模块随主分支提供，设置中可启停。打开 `/#campus-map`，选择日期查看安排；点击日程或建筑查看详情，使用“电梯位置”切换资料图层。手机上点击安排会把对应地图位置带回可视区域。

合成检查覆盖具体楼号、相近楼号排除、多地点歧义、北京时间与截止语义、依赖停用、取消／请假／调课、账号切换、几何数据完整性、校门别名、道路坐标范围、固定屏幕字号和标签碰撞；完整检查仍使用仓库 `check.ps1` / `check.sh`。界面验收检查日期切换、课程定位、搜索、缩放、地图展开、校门地址、电梯来源链接、手机宽度和切页样式清理。运行 `node modules/campus-map/checks/check_web.mjs <本机地址>` 使用合成日程和维护记录，验证真实框架导航、课程深链接、日期请求乱序、选路与封闭、四种主题的电脑／手机布局、时间表不可用及卸载清理；截图保存在 `.codex/tmp/campus-map-ui/`。
