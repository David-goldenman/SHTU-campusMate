# 校园后台助手

独立模块 `campus-agent`，包含 Python 生命周期服务、官方 DeepSeek Harness 原生插件和常驻通知入口。业务页面继续通过各自 API 提供资料，框架仅管理通用模块目录、布局与入口。

## 检查与资料范围

默认开启，每 25 秒比较已启用来源的缓存内容、故障状态、用户个人安排及邮箱偏好，合并一轮变化后运行官方 Harness。首次运行先为已有资料建立基线；后续新邮件会触发复核。修改筛选偏好时复核最近五封；“检查一次”选择最近三封，每轮最多四封、24 次工具调用。较早邮件可在邮箱中单独或批量复核。资料没有变化时只读取本地状态。网页常驻入口首次连接后提供当前本机回调地址，之后后台可继续运行至应用关闭。

服务通过 `context.modules()` 和各模块 `/openapi.json` 发现只读接口，按需调用公开 API。模型接收本轮服务目录、状态、完整偏好及实际查询到的邮件、课程或通知文字；邮件正文至多 14000 字符。邮箱地址和手机号从分类正文中替换，学校密码、Cookie、sid、API Key 与工具令牌留在本机。模型使用共享 AI 设置，界面在邮箱偏好及 AI 设置中说明发送范围。

原生工具包括 `campus_read`、`campus_mail`、`campus_classify`、`campus_propose`、`campus_notice`、`campus_sync`。工具令牌只绑定当前任务和账号版本，任务结束立即释放。只读路径来自实际 OpenAPI；下载和工具授权路径不列入目录。写操作为固定业务动作；同步重试仅用于失败状态，每个服务每轮一次。收到需要登录或验证的状态时提醒用户处理。

邮件原文通过 `campus_mail` 按本轮名单读取，通用读取只提供邮件偏好，聚合 API 中的邮件也按同一名单过滤。学习助手向后台提供学习档案；对话历史通过首页自身的会话管理访问。

## 通知与日程

邮件分类写入 `mail/review-results`，由邮箱检查资料指纹、schema 和连续原文。重点及兴趣推荐汇入通知中心，其余保留在邮箱。手动分类优先，偏好更新后的旧分类不会写成安排。其他来源通过本轮实际读取的标识和原文生成通知或活动建议。

邮箱页面单独完成的语义复核也会被下一轮检查发现，直接复用有效分类生成通知和建议，保持相同资料的处理标记，避免为结果再次调用模型。聚合页面的重复计算与后台自己的导入结果不作为新来源变化。故障来源恢复同步后更新原有提醒的状态。

未来活动需要可核对的日期和开始时刻；只有月日时，年份须与收件年份一致。报名截止时间不作为活动时间。普通活动、讲座保留 `pending` 建议，由用户点击“参加并加入时间表”或在首页明确表达参加意愿后确认。形策自动安排另要求：邮件明确计入形策考勤、个人设置仍需完成、分类保护有效、日期已核对，且没有手动覆盖。普通政治讲座不据此认定为形策考勤。

安排通过时间表 `/events/import` 携带账号版本及稳定 `origin_id` 导入，重复执行返回已有记录并保留手动修改。确认或拒绝状态持久化，已确认后被用户删除的安排也不会由同一建议反复添加。目前每份来源提取一项活动；多场次通知可在时间表手动补充。时间证据不完整的事项保留核对提示。

## HTTP API

前缀 `/api/v1/modules/campus-agent`，普通写入由框架 CSRF 保护。

| 接口 | 用途 |
| --- | --- |
| `GET /status` | `{available,owner,enabled,running,last_checked,last_run,summary,error,pending_count,proposals,notices}`；last_run 保留已完成综合检查的时间和邮件／工具计数 |
| `PUT /settings` | `{enabled:boolean}`；关闭时取消当前运行 |
| `POST /check` | 请求检查最近资料，202，不阻塞页面 |
| `GET /proposals` | 当前账号的活动建议及确认状态 |
| `POST /proposals/{id}/accept` | 明确参加并导入时间表；重复确认返回原状态 |
| `POST /proposals/{id}/dismiss` | 记录不参加 |
| `POST /tools/{read,mail,classify,propose,notice,sync}` | 当前 Harness 任务的短期工具路由 |

普通状态保存在本模块 Store，按共享账号组合版本隔离；工具令牌只在内存中。`start` 管理唯一检查线程，`stop` 设置取消事件、唤醒并等待其结束。网页 `background.js` 在切页时保留，停用或刷新时清除定时器与样式。新的通知只提醒一次，相同资料保留已读；已有历史通过通知入口查看。

`checks/check_agent.py` 使用合成来源和模型，验证变化合并、分类回写、必需与可选安排、参加确认、去重、手动修改、账号隔离与线程清理。`checks/check_harness.py` 验证真实官方运行时及本插件的工具注册／回调；`checks/check_campus_workspace.mjs` 验证邮件、课程、通知与常驻入口交互。
