# 群消息

把本人微信、QQ 中选定课程群的文字通知整理成有原文依据的事项。默认没有连接、没有选群、不发送聊天给 AI；本机服务保持运行时才自动检查。

## 使用

1. 微信：正常登录 Windows 微信 4，检测本人主实例并选择本人的 `db_storage`，勾选只读授权。检测仅查询进程元数据，过滤带 `--type` 的文字识别、播放器等辅助进程；保留当前 Windows 用户的多个真实主实例，只有一个时自动选中。命令行不可读取的进程不列出，检测不读取聊天或捕获密钥。复用 QJQ 的本机密钥捕获、SQLCipher 页面校验和已提交 WAL 合并；首次授权只返回群列表。也可选择已完成导出的可读微信 4 快照。
2. QQ：按照卡片中的三步引导准备 NapCat／OneBot HTTP 服务，填写回环地址与连接口令（Access Token）。口令在 NapCat“网络配置 → HTTP 服务端 → Token”中设置或复制，与 QQ 密码和管理页面登录口令分开。连接成功后仅展示群列表，选择并保存群后才开始同步。仅调用读取接口，不发送消息、不安装或启动 QQ 适配器。
3. 默认显示本学期候选课程群。群名和关联课程采用紧凑列表，根据课程代码、中文名及各平台别名预填唯一匹配，可用“勾选已匹配课程群”批量选择；多课程候选不自动决定。需要修正时打开“显示其他群，手动关联”，选择本学期课程。点击列表上方固定位置的“保存关联”统一确认，保存后开始同步所选群；状态栏明确显示未保存、保存中、已保存或失败，失败保留草稿，可重试或撤销修改。缺少有效课程时提示补全，搜索和状态刷新保留未提交修改。已保存的关联不会被后续自动匹配覆盖。
   群内“自动整理与消息”按需展开；查看消息、可信发送者和整理操作使用已保存的关联，修改后须先保存。同步频率与 AI 授权独立折叠：微信可每 5／15／30 分钟同步；QQ 可每 20 秒／1／5／15 分钟轮询。每次同步更新近 7／30 天的正文窗口，首次提取覆盖整个已同步范围。
4. 先同步一次即可查看发言者，再指定可信老师／助教（按稳定账号标识，不凭昵称）。单独选择自动提取与自动应用；开启自动提取前确认发送相关正文及前文给当前 AI 服务。手动“整理一次”也说明发送范围。
5. 事项可查看逐条引用，确认信息、加入本地待办／日程、忽略或撤销。调课先产生核对待办，不直接修改教务课程节次。活动始终需要明确参加。

自动应用要求课程绑定、可信的新消息引用、可核实时间、无疑问措辞，且所选群策略仍有效。课程平台已有相似作业时要求人工核对；群事项只创建本地计划，不改变学校提交状态。Quiz／考试自动入日程要求完整时段与可完整比较的课表；重叠、不完整时段和缺失来源均转人工核对。已有目标被手动编辑或删除后不覆盖、不自动重建。取消通知需人工确认。

“课上交 HW2”保留日期和提交场景，不补截止钟点；“补课 20:15 开始，补课结束后有 Quiz”拆为补课安排与日期级 Quiz。提取校验拒绝把前一个事项的钟点借给“课后／补课后”的 Quiz，原文引用继续保留。

界面使用共享的主操作、次操作和删除按钮，沿用四个主题的颜色与表面层次；PRTS 使用直角组件。群消息、来源与选群、提取结果分级显示，弹窗提供可访问名称。

QQ 首次配置：按 [NapCat Windows 启动说明](https://napneko.github.io/guide/boot/Shell) 启动并登录本人 QQ，在“网络配置”新建并启用 HTTP 服务端，Host 使用 `127.0.0.1`、端口例如 `3000`，设置 Token 后把同一口令填入工作台。管理页面通常使用 `6099`，以 NapCat 启动提示为准；它与工作台要连接的 HTTP 接口分开。详见 [官方配置说明](https://napneko.github.io/config/basic)。连接口令可临时显示核对，提交后清空并重新隐藏；失败重试在当前页面保留接口地址，账号切换时清除该地址草稿；持久凭据只写入 `context.secrets`。失败提示区分接口不可达、口令验证失败、地址不匹配与 QQ 尚未登录。

## 范围与兼容性

- 仅已关联本学期课程的所选群可以同步、查看原文或发送给 AI。保存设置、每次采集／提取及事项应用前复核课程中心公开 `/identities`；新学期、课程停用或关联失效时停止对应群读取，保留原选择供用户修正，不删除已生成的本地计划。修改关联后，原课程的事项不再当作新课程事项发布。
- 名称匹配仅使用群名称和课程身份，不读取正文、不调用模型。显式标记其他学期的群不自动匹配；同名冲突、仅部分名称相似均需手动选择。`EE130` 与 `EE130P` 分别匹配，避免把电磁学和课程设计混为一门。未匹配群列表只展示已连接账号的群元数据，保存本学期课程关联之前不读取其消息。

- 微信继承代码的已记录设备版本为 **4.1.15.13**。本次移植通过合成加密 SQLite／WAL 与浏览器测试，尚未在此主项目执行真实课程群增量验收。版本变化先暂停，用已有授权检查兼容性，经页面确认后恢复；定时器不重新捕获密钥。
- 微信只能读客户端已经下载到本机的数据。原库只读；临时完整分片解密后仅将所选群与相关发送者写入模块快照。每个原库分片与其 WAL 合计上限 8 GiB，所选快照上限 512 MiB，每群最多 20000 条；失败保留上一份有效快照。密钥保存在 `context.secrets`。
- QQ 每群每轮最多最近 100 条，不具备反向分页补齐。窗口未覆盖上次进度时持续显示历史可能有缺口；后续成功轮询不能清除这个提示。尚未进行本项目真实 QQ 验收。未知发送时间保留为空，不用读取时间冒充。
- 支持文字、引用回复和文件／链接标题。图片、语音、视频、链接目标与附件正文不读取。长正文保存上限 64000 字符，单次 AI 摘取每条最多 8000 字符并标明截断；每批最多 60 条新增、80 条邻近前文，并优先加入可找到的回复原文。
- 未选群、暂停或移除连接不会删除已生成的本地事项。换聊天账号、取消选群或移除连接后，旧范围的通知自动收起；重新选择后可恢复。每次同步清理所选群窗口外的缓存；暂停期间保留上次缓存与有效快照，提取结果和原文引用保留至清除模块数据。移除连接删除对应密钥。宿主学校账号版本与聊天连接均隔离。

## 接口与集成

前端使用模块内 `/status`、`/wechat/discovery`、`/wechat/connect`、`/wechat/snapshot`、`/qq/connect`、`PUT /sources/{source}`、`/sources/{source}/sync`、`/sources/{source}/pause`、`/stop`、`/messages`、`/senders`、`/extract`、`/items` 和 `/items/{id}/decision`。选群保存、事项确认携带显示时的 `expected_revision`。

`GET /courses` 返回本学期 `items`、`current_semester`、`account_revision` 与按来源／群 ID 组织的 `matches`。每项匹配包含 `status/course_id/reason/candidates`，状态为 `saved/automatic/ambiguous/unmatched/other_term/inactive`。建议不写入选群设置。`PUT /sources/{source}` 的每个选群必须带有效本学期 `course_id`，空数组仍可停止所有群。`/status.sources[source].course_scope` 提供 `available/current_semester/active_group_ids/blocked_groups`，标明当前允许读取的范围。

对其他模块提供只读 `GET /snapshot` 与 `/facts/{id}`：仅包含已确认或已应用的课程事实，不含连接凭据和群原始流水。课程中心将其加入 announcements，学习助手可检索并引用；通知通过 `/notifications/imports` 使用稳定 ID 更新。后台助手跳过本模块原文工具和已管理通知、日程，避免重复分类。模块缺失时课程中心仍可运行。

原生 Harness 插件只开放 `group_submit`，没有网络或副作用工具。Python 对结构、引用、来源版本、时间和账号再校验后保存，失败不推进游标。应用与撤销通过学习事务 `/work/commands`、时间表 `/commands` 的版本检查和幂等请求完成，调用前保存请求，返回后保存回执。网络结果不明时重试原请求；目标手动变更时停止并提示。

## 来源与检查

`server/native/`、微信文字解析及合成加密夹具改编自团队 QJQ 的 `wechat_crypto.py`、`wechat_native.py`、`wechat_version.py`、`wechat_snapshot.py`、`wechat.py` 和 `test_wechat_native.py`，保留 `native/WCDB_LICENSE`。QQ 本机只读客户端复用团队 WYT 的 `message-hub/source_api.py`，补充账号、群、稳定发送者与缺口状态校验。旧应用的独立 AI 客户端、全局工作线程和私有数据库未接入。

`checks/check_discovery.py` 验证多个微信主实例、辅助进程过滤、当前用户边界、进程退出和元数据不可读取；`checks/check_qq_connection.py` 验证本机服务、口令、接口地址及 QQ 登录失败的分项提示与秘密不泄漏；`checks/check_native.py` 验证加密页、已提交 WAL、选群、7 天范围、版本变化、取消及失败清理；`checks/check_flow.py` 验证增量、引用、信任、换号、暂停及真实公开待办／日程接口的更新与撤销。这些检查纳入项目 `check.ps1`／`check.sh`；官方 Harness 合成模型检查同时加载本插件。`node modules/group-messages/checks/check_web.mjs <本机地址>` 使用浏览器内合成数据，不读取个人聊天、不保存真实设置，截图进入 `.codex/tmp/group-messages-ui/`。
