# 群消息

把本人微信、QQ 中选定课程群的文字通知整理成有原文依据的事项。默认没有连接、没有选群、不发送聊天给 AI；本机服务保持运行时才自动检查。

## 使用

1. 微信：正常登录 Windows 微信 4，检测本人实例并选择本人的 `db_storage`，勾选只读授权。复用 QJQ 的本机密钥捕获、SQLCipher 页面校验和已提交 WAL 合并；首次授权只返回群列表。也可选择已完成导出的可读微信 4 快照。
2. QQ：使用已运行、已登录本人的 NapCat／OneBot HTTP 服务，填写回环地址与 Access Token。仅调用读取接口，不发送消息、不安装或启动 QQ 适配器。
3. 勾选群、关联课程并保存。微信可每 5／15／30 分钟同步；QQ 可每 20 秒／1／5／15 分钟轮询。每次同步更新近 7／30 天的正文窗口，首次提取覆盖整个已同步范围。
4. 先同步一次即可查看发言者，再指定可信老师／助教（按稳定账号标识，不凭昵称）。单独选择自动提取与自动应用；开启自动提取前确认发送相关正文及前文给当前 AI 服务。手动“整理一次”也说明发送范围。
5. 事项可查看逐条引用，确认信息、加入本地待办／日程、忽略或撤销。调课先产生核对待办，不直接修改教务课程节次。活动始终需要明确参加。

自动应用要求课程绑定、可信的新消息引用、可核实时间、无疑问措辞，且所选群策略仍有效。课程平台已有相似作业时要求人工核对；群事项只创建本地计划，不改变学校提交状态。Quiz／考试自动入日程要求完整时段与可完整比较的课表；重叠、不完整时段和缺失来源均转人工核对。已有目标被手动编辑或删除后不覆盖、不自动重建。取消通知需人工确认。

## 范围与兼容性

- 微信继承代码的已记录设备版本为 **4.1.15.13**。本次移植通过合成加密 SQLite／WAL 与浏览器测试，尚未在此主项目执行真实课程群增量验收。版本变化先暂停，用已有授权检查兼容性，经页面确认后恢复；定时器不重新捕获密钥。
- 微信只能读客户端已经下载到本机的数据。原库只读；临时完整分片解密后仅将所选群与相关发送者写入模块快照。每个原库分片与其 WAL 合计上限 8 GiB，所选快照上限 512 MiB，每群最多 20000 条；失败保留上一份有效快照。密钥保存在 `context.secrets`。
- QQ 每群每轮最多最近 100 条，不具备反向分页补齐。窗口未覆盖上次进度时持续显示历史可能有缺口；后续成功轮询不能清除这个提示。尚未进行本项目真实 QQ 验收。未知发送时间保留为空，不用读取时间冒充。
- 支持文字、引用回复和文件／链接标题。图片、语音、视频、链接目标与附件正文不读取。长正文保存上限 64000 字符，单次 AI 摘取每条最多 8000 字符并标明截断；每批最多 60 条新增、80 条邻近前文，并优先加入可找到的回复原文。
- 未选群、暂停或移除连接不会删除已生成的本地事项。换聊天账号、取消选群或移除连接后，旧范围的通知自动收起；重新选择后可恢复。每次同步清理所选群窗口外的缓存；暂停期间保留上次缓存与有效快照，提取结果和原文引用保留至清除模块数据。移除连接删除对应密钥。宿主学校账号版本与聊天连接均隔离。

## 接口与集成

前端使用模块内 `/status`、`/wechat/discovery`、`/wechat/connect`、`/wechat/snapshot`、`/qq/connect`、`PUT /sources/{source}`、`/sources/{source}/sync`、`/sources/{source}/pause`、`/stop`、`/messages`、`/senders`、`/extract`、`/items` 和 `/items/{id}/decision`。选群保存、事项确认携带显示时的 `expected_revision`。

对其他模块提供只读 `GET /snapshot` 与 `/facts/{id}`：仅包含已确认或已应用的课程事实，不含连接凭据和群原始流水。课程中心将其加入 announcements，学习助手可检索并引用；通知通过 `/notifications/imports` 使用稳定 ID 更新。后台助手跳过本模块原文工具和已管理通知、日程，避免重复分类。模块缺失时课程中心仍可运行。

原生 Harness 插件只开放 `group_submit`，没有网络或副作用工具。Python 对结构、引用、来源版本、时间和账号再校验后保存，失败不推进游标。应用与撤销通过学习事务 `/work/commands`、时间表 `/commands` 的版本检查和幂等请求完成，调用前保存请求，返回后保存回执。网络结果不明时重试原请求；目标手动变更时停止并提示。

## 来源与检查

`server/native/`、微信文字解析及合成加密夹具改编自团队 QJQ 的 `wechat_crypto.py`、`wechat_native.py`、`wechat_version.py`、`wechat_snapshot.py`、`wechat.py` 和 `test_wechat_native.py`，保留 `native/WCDB_LICENSE`。QQ 本机只读客户端复用团队 WYT 的 `message-hub/source_api.py`，补充账号、群、稳定发送者与缺口状态校验。旧应用的独立 AI 客户端、全局工作线程和私有数据库未接入。

`checks/check_native.py` 验证加密页、已提交 WAL、选群、7 天范围、版本变化、取消及失败清理；`checks/check_flow.py` 验证增量、引用、信任、换号、暂停及真实公开待办／日程接口的更新与撤销。两项纳入项目 `check.ps1`／`check.sh`；官方 Harness 合成模型检查同时加载本插件。`node modules/group-messages/checks/check_web.mjs <本机地址>` 使用浏览器内合成数据，不读取个人聊天、不保存真实设置，截图进入 `.codex/tmp/group-messages-ui/`。
