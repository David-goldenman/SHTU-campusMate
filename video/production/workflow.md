# 制作与修改流程

1. 同步其他对话已经合并的 main，读取新增功能的 README、公开接口与实际页面。PR 整合由负责对话完成；本任务只读取状态和同步代码。记录当前提交与 CI，再重启隔离演示服务。
2. 在 `brief.md` 明确受众、叙事与取材范围。真实通知、作业与已存对话保存在 `source-data.json`；公开来源、课件页码与培养方案有独立记录。群聊身份、学生状态与个别安排使用明确的演示数据。
3. 在 `src/film.json` 编辑章节、标题、时长及制作名单，在 `src/operations.json` 编辑输入、点击、滚动、工具进度、流式输出、路线与镜头目标。
4. 运行 `scripts/record.mjs`：桌面 1472×720 CSS 像素、1.875 设备像素比，源帧 2760×1350；手机 430×860 CSS 像素、2 倍设备像素比，源帧 860×1720。浏览器关闭缓存，前后核对项目界面源码指纹，代码变化时重新录制。
5. 产品 HTML、CSS、JavaScript、主题与地图数据来自真实源码。真实业务 API 在网络层阻断，演示接口在浏览器中接管；未知接口与前端异常使录制失败。聊天使用原生 NDJSON 流协议，通知使用实际后台组件，课程群与日程的确认、回执和撤销只影响演示内存。
6. 每个变化后的 PNG 和保持帧数进入 `.codex/video/recordings/<id>/`。取景区域由实际 DOM 测得，记录到 `src/framing.json`；日程与近四周网格另有局部截图。编码器按 60 fps 发送每一帧到 FFmpeg。
7. Remotion 将桌面素材放入 1840×900 演示区域。镜头推近目标、稳定阅读、回到全景；章节以 Nord 底色、曲线运动和下一功能标题衔接，完整切换为 2.4 秒。界面内页面展开为 0.85 秒，鼠标用 1 秒曲线到达操作目标，动作结束与出场之间保留约 3 秒以上阅读停留。时间参数及修改位置见 `motion.md`。手机使用同一响应式前端，片尾逐项呈现团队成员。配乐从指定 OGG 选段衔接，最终首尾淡入淡出。
8. 运行 `npm run check`，检查全部录制的尺寸、帧数、操作时间、取景、当前源码指纹、鼠标连续性与到达误差、阅读停留和流式事件，并生成大纲和完整脚本；运行 `npm run stills` 逐帧查看版式、镜头目标、连续转场及团队文字。
9. 运行 `npm run render`。覆盖输出前，`scripts/archive.mjs` 校验并保留已有 MP4。运行 `npm run verify` 完整解码并提取关键帧、封面和预览，成功后归档新成片，更新 `player.html` 的版本选项。
10. 导出前再读取 main 和远程 PR 状态。如相关页面有更新，重新启动隔离服务、录制受影响段落，再检查及导出。最终结果保存在 `production/validation.md`。

最终工程与成片保存在 `video/`，历史版本仅复制 MP4；缓存、下载、中间帧、浏览器与隔离服务均保存在项目 `.codex/`。
