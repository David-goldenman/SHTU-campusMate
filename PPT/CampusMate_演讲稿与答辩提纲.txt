逐页演讲稿

1. CampusMate　0:00 - 0:15

大家好，我们是 AAA罗德岛工程部。我们做的 CampusMate，是一个面向大学生日常学习的 AI 工作台。它把课程、作业、邮件和日程接在一起，帮助我们看清接下来要做什么。

2. 一个学习任务，分散在多个入口　0:15 - 0:40

一个普通的学习周里，我们要去教务系统找课表，在 Blackboard 找课件，到 Gradescope 查作业，再从邮箱和 Piazza 追通知。真正耗费注意力的是，把这些信息重新拼成自己的安排。所以我们先解决一个具体问题：打开一个地方，知道本周先做什么，以及判断的依据在哪里。

3. 课程与作业，按同一门课汇总　0:40 - 1:15

课程中心按课程代码和学期关联不同平台，也支持手动关联。进入同一门课，就能看到可用的资料、作业、讨论和录播，不必再记住内容发在哪个平台。作业管理把截止和来源放在一起，并区分草稿、提交、评分等状态。来源没有确认的信息会保留待核实，避免把已经交过的作业反复提醒。

4. 邮件分类，结合你的学习需要　1:15 - 1:50

邮箱先用规则初筛，再由 AI 结合年级、在修课程、兴趣和完成状态复核。比如，仍需完成形策的同学，会优先看到原文明确认定考勤的讲座。用户也可以直接写“关注机器人讲座，已结束活动保留摘要”。分类可以展开查看理由和原文，手动调整优先保留；日周总结覆盖最近最多一百封已同步邮件。

5. 一句话安排日程，结果可以核对　1:50 - 2:25

当用户说“帮我把下一次形策讲座加入时间表”，助手会先读取通知和课表，再调用本地日程工具，保存成功后返回回执。后台也会关注资料变化，把重要更新放进通知中心；活动需要明确确认参加。时间表同时整合课程、考试、截止和个人安排，支持近四周预览和日历文件导出。加入本地日程后，学校要求的报名仍需完成。

6. 复习建议，能回到课件的具体页　2:25 - 3:05

再看一个学习场景：这周作业多，想安排一次条件概率复习。助手先查询作业和截止，再检索这门课的资料，给出先完成哪份作业、何时复习的建议。回答里可以展开 Lecture Slides L2 第五页的原文，并打开来源继续核对。这个页码已经和课件核对过。服务端还会检查引用确实来自本次读取的资料，资料不足时直接说明缺口。

7. 选课建议，结合已有学业信息　3:05 - 3:30

同样的资料能力也能用于选课。用户说明自己对机器人感兴趣，助手结合已有课程记录和培养方案，继续查询课程目录、教学大纲与先修要求，再讨论学习负担。这样，建议能具体到要核对哪些课程。未来学期是否实际开课，还需要以学校当期目录为准。

8. AI 工具调用与结果校验　3:30 - 4:10

技术上，我们用 FastAPI 和原生前端搭建统一工作台，目前集成十九个独立模块。共享服务管理学校登录、模型和本机加密凭据，模块通过公开 API 协作。AI 使用官方 DeepSeek Harness 原生插件，按问题调用工具读取资料。返回结果时，服务端校验原文引用和账号版本；涉及修改，还要检查明确意愿并保留回执。所需学习资料会发送到用户选择的模型服务。

9. 同一份学习信息，多种使用方式　4:10 - 4:35

日程也能带进常用日历。时间表可把近四周课程和作业截止导出为 .ics 文件，保留课程地点和作业提醒，交给支持导入的苹果、安卓或鸿蒙日历。手机网页仍可按天查看安排。外观提供 Nord、观星台、星夜手记和 PRTS 四套主题，并保存选择。

10. CampusMate　4:35 - 5:00

现在，校园来源读取和带引用问答已有真实账号验收，本地日程操作也通过了隔离验证。接下来，我们会扩大真实课程场景试用，继续完善地图和课程群消息接入。我们希望，打开 CampusMate，就能把分散的信息整理成每天可以执行的学习安排。谢谢大家。

答辩提纲

和直接使用通用聊天助手相比，有什么价值？
CampusMate 已经连接校园来源，按课程和账号组织资料。助手可以查询当前作业、课表和培养方案，读取课件的具体页，返回原文引用，并在用户明确要求后调用本地日程或学习事务工具。价值在于资料、建议与操作连在同一个工作台中。

AI 如何避免编造校园信息？
课程、作业与校园事实需要读取实际来源。引用提交后，服务端检查来源属于本轮任务、引文来自原文，并保留页码和原文件入口。账号或资料变化会阻止过期结果写回。引用检查可以约束证据来源，回答的推理和建议仍需要用户判断。

AI 可以改什么？
可以按明确指令维护本地日程、学习计划、一次性提醒与本地作业进度，保存成功后返回回执。活动要确认参加。原站提交状态、正式选课、学校报名和审批仍以原系统为准。本地课程调整也保留适用范围与修改记录。

隐私与数据保存在哪里？
学校凭据和模型 Key 通过当前 Windows 用户的 DPAPI 加密，聊天、偏好、缓存与普通记录保存在本机并按账号版本隔离。AI 按问题把所需资料发送到用户选择的模型服务。更换电脑或 Windows 账号后，需要重新配置凭据。

学校平台是否都能使用？
真实来源验收记录覆盖教务课表、Blackboard、Gradescope、Coremail、ELRC 与 Piazza 的登录和基础同步，具体范围与日期见 docs/LIVE_ACCEPTANCE.md。E 云课堂已实现接入并有合成回归。学校协议、网络、验证码和会话有效期会影响使用；来源失败时保留已有缓存并显示状态。

邮件为什么适合校园场景？
分类把当前课程、年级、形策或心理活动需求及兴趣一起考虑，保留分类理由和原文。明确的考勤认定与普通讲座分别处理。手动分类优先，偏好变化后重新复核；通知与活动建议沿用同一结果。当前读取与总结范围是最近最多 100 封已同步收件箱邮件。

课件读取能做到什么？
可按页读取 PDF、PPTX 和文本，扫描 PDF 与图片支持可配置的直接识图或本地 OCR。视频示例采用 Lecture Slides L2 第 5 页，原文与页码已核对；真实账号验收还记录了 PDF 读取。识图结果会区别于原文，扫描件效果与更多附件格式仍需继续验收。

选课建议能否保证下学期有课？
建议结合已有课程记录、培养方案、课程目录和教学大纲，并考虑用户方向与负担。未来学期是否实际开设、时间冲突和正式选课结果，需要以学校当期公布信息为准。

地图与微信群、QQ 做到了哪一步？
地图已提供建筑定位和室外步行试用，通行、入口及无障碍条件需要现场核验。群消息通过本人微信主实例与 QQ 本机 OneBot 接入。微信检测过滤辅助进程，QQ 提供三步连接引导及分项失败提示；支持选群、原文依据、确认与撤销。主项目真实课程群增量验收待完成，QQ 最近消息窗口可能遗漏历史。第 13 页可用于补充。

怎样把课程安排带进手机日历？
时间表的“导出日历 (.ics)”下载近四周（上周、本周、下周、下下周）的课程课表与作业截止，包含课程地点、稳定标识和作业提醒。苹果、安卓与鸿蒙日历需要提供 .ics 文件导入入口，具体步骤因应用与机型而异。活动和个人安排在工作台时间表中查看。当前完成了导出结构检查，实际导入后的显示与提醒行为仍需相应设备验收。

手机端和桌面端是什么关系？
手机画面是同一前端的响应式网页视口，桌面周表在窄屏按天组织。当前交付目标是 Windows 本地网页验证，后续再接入桌面壳。移动访问部署与实机体验需要按实际环境验证。

有多少用户、节省了多少时间？
当前阶段是团队的功能验证与真实来源验收，还没有可以对外报告的用户规模、留存或节省时间数据。下一步通过校内小范围试用，观察信息查找、作业核对与安排任务的实际使用体验。

四人团队如何协作？
项目按框架、共享认证、共享 AI 与独立业务模块划分边界。通过文档化 API 协作，功能分支经 PR 集成，CI 使用与本地一致的检查入口。当前集成 19 个模块。具体个人分工应由成员按实际经历介绍，仓库提交不单独作为贡献评价。
